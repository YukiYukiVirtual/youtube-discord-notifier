# YouTube 配信・動画 通知ツール（Discord Webhook 版）

指定した YouTube チャンネルを定期的にチェックして、Discord のチャンネルに通知を投稿する小さな Python プログラムです。

通知されるもの：
- 📅 配信枠が立てられた時（開始予定つきの枠のみ）
- 🔴 配信が開始した時
- ⏹️ 配信が終了した時
- 🎬 通常動画が投稿された時
- 📝 コミュニティ投稿（ベストエフォート：YouTube 側のページ仕様に依存します）

## 🔐 秘密情報は暗号化して受け渡します

導入のときに入力する **Webhook URL と YouTube APIキーは、あなたのブラウザの中で暗号化されてから Muse に渡ります**。

- チャットに秘密情報を貼る必要はありません
- 暗号化された状態でしか渡らないので、途中で読まれる心配がありません
- 受け渡しが終わったら、復号に使う鍵は破棄されます

安心して使ってください。仕組みの細かい話は、導入を担当する Muse 向けの指示書（FOR_MUSE.md）に書いてあります。

## このツールの前提：Muse の上で常駐させる

このツールは **Muse の作業環境（Ubuntu）の上で動かし続ける** ことを前提に設計されています。Muse の作業環境は基盤の更新で入れ替わることがあり、プロセスが止まってしまう場合があります。そこで、Muse の標準機能であるハートビート（30分ごとに自動で動くチェック）が「止まっていたら起こし直す」役割も一緒に設定し、落ちても自動で戻るようにします。作業環境の入れ替わり直後は、ハートビートのタイミングにより最大で30分ほど起動が遅れることがあります。

もちろん、自分の Linux サーバーに入れて動かすこともできます（後半の「手動でセットアップする場合」）。

## 必要なもの

- Muse（このツールを常駐させる作業環境）
- 入力は次の3つだけです
  1. **通知先の Discord Webhook URL**
  2. **YouTube Data API v3 の APIキー**
  3. **監視したいチャンネル（チャンネルID または @ハンドル）**

## 導入方法

### 方法1：Muse で使う（おすすめ）

**GitHub の URL を、自分の Muse に伝えてください**：[github.com/YukiYukiVirtual/youtube-discord-notifier](https://github.com/YukiYukiVirtual/youtube-discord-notifier) を渡して「このツールを導入して」と言うだけです。あとはあなたの Muse がステップバイステップで導入を進めてくれます（設定の用意、暗号化フォームへの入力の案内、常駐化、自動復旧の設定、動作確認まで）。

あなたがやることは、主に次の2つだけです：

- 事前準備（Webhook の作成と APIキーの発行。Muse がその都度、手順を案内してくれます）
- 途中で出てくる暗号化フォームへの入力

### 方法2：自分のサーバーで使う

自分でホストしている Linux サーバーなどに入れる場合は、同じファイルが使えます。自分のマシンの中だけで完結するので、secret.py に直接値を書いて構いません（暗号化フォームは不要です）。

```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
cp secret.py.example secret.py   # 値を自分で書き込む（公開・共有厳禁）
# config.py の CHANNEL_ID と CHANNEL_NAME を書き換える
./venv/bin/python -u main.py
```

常駐化には systemd ユーザーサービスが使えます（ユニットの例は FOR_MUSE.md にあります）。この場合ハートビートは付きませんが、`Restart=always` により通常の異常終了からは自動復帰します。

## 事前準備

方法1（Muse）の場合は、Muse がその都度案内してくれるので、読み飛ばして大丈夫です。

### 1. Discord Webhook を作る

通知を投稿したいチャンネルの「チャンネル設定 → 連携サービス → ウェブフック → 新しいウェブフック」で作成し、URL を手元に用意しておきます（チャットには貼らないでください。入力は暗号化フォームから行います）。

### 2. YouTube Data API キーを発行する

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを新規作成
2. 「APIとサービス → ライブラリ」で **YouTube Data API v3** を検索して有効化
3. 「APIとサービス → 認証情報 → 認証情報を作成 → APIキー」でキーを発行
4. （推奨）発行したキーを編集し、「APIの制限」で YouTube Data API v3 のみに制限する

無料枠は 1 日 10,000 ユニット（太平洋時間の深夜にリセット）。初期設定の 20 秒間隔ポーリングでは約 8,640 ユニット/日を使います。

### 3. 監視したいチャンネルを用意する

チャンネルは、チャンネルID と @ハンドルのどちらでも指定できます。簡単なのは @ハンドルです：

- **@ハンドル**：チャンネルページの URL が `youtube.com/@yukiyukivirtual` の形なら、その `@yukiyukivirtual` の部分がハンドルです。そのまま使えます
- **チャンネルID（UC...）**：YouTube Studio の「設定 → チャンネル → 詳細設定」で確認できます。チャンネルページの URL が `youtube.com/channel/UC...` の形なら、その `UC...` でも大丈夫です

## 仕様と注意事項

- **エンコーダ配信の扱い**：エンコーダ配信の画面を開いただけで作られる「開始予定のない待機オブジェクト」は、枠として告知しません（開始・終了は通知します）。開始予定が付いた枠は、開始までの時間が短くても告知します
- **停止中の取りこぼし**：本体が止まっている間に始まった配信は、復旧後のチェックで「遅れて開始通知」になります。ただし、止まっている間に始まって終わった配信は検知できません（枠を告知済みだった場合はキャンセル扱いになります）
- **API が使えない時**：API のエラー（クォータ超過など）の間は、自動でスクレイピング方式に切り替えて動作を続けます（精度と速さは落ちます）
- **プレミア公開**も配信と同じ遷移で扱われるため、開始・終了が通知されます
- **状態ファイル**：`state.json` に既読状態を保存します。消すと初回起動扱いになり、その時点の既存分が「見済み」として再取り込みされます（過去分の通知は出ません）
- **secret.py の管理**：Webhook URL と APIキーが入っています。Git 管理する場合は `.gitignore` 済みか必ず確認してください（このフォルダには同梱済みです）
- **復旧のタイミング**：本体が止まった場合の復旧は、Muse のハートビート（30分ごと）のタイミングで行われます。ハートビートのチェックは Muse の利用量を少しだけ使います

## 設定について

チェック間隔（初期設定は20秒）や通知の文面などは、`config.py` で変更できます。変えたい時は、Muse に「チェック間隔を60秒にして」のように頼めば、変更と再起動までやってくれます（自分のサーバーで使っている場合は、config.py を編集して再起動してください）。
